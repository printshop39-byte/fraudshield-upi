          Why This Approach
          
          
          
            
          Problem: WhatsApp strips EXIF metadata and re-compresses
            every image — so classical image forensics (ELA, compression analysis) becomes
            unreliable on exactly the images we receive.
          
            
          Solution: Anchor detection on data that cannot be
            faked — the UTR reference number, the payee VPA, and the actual bank settlement
            record. Image hashing handles replay; rules handle the rest.
          
            
          Result: Every verdict is explainable. The agent
            sees exactly which check failed — critical for trust and for dispute handling.
          
          
          
          
          
            Note: The system never accuses a customer. Output language is
            "could not verify", never "this person is a fraudster" — an important
            legal and ethical safeguard.
          
          
        
          
      
          

      
          
        
          Experimental Finding — Why We Rejected Perceptual Hashing
          
        
          
          Our first design used a perceptual hash (pHash/dHash) to detect re-sent
          screenshots. We implemented it, measured it, and disproved our own
          approach. A perceptual hash downscales the image to a small grid, so it
          encodes layout — and every UPI success screen from the same app has an
          identical layout. The amount and payer text, the only things that actually
          differ, vanish on downscale.
        
          
        
          
          
          
            Hash gridBits
            Re-compressed replay
          (should be LOW)          		
            Two different genuine payments
          (should be HIGH)          		
          
          
          
            
          16×16256
                29 bits differ
                3 bits differ
          
            
          32×321024
                44 bits differ
                1 bit differs
          
            
          64×644096
                212 bits differ
                5 bits differ
          
                    
        
          
        
          
          The signal is inverted. A genuine replay differs
          more than two unrelated payments do, because WhatsApp re-compresses every
          image it forwards. No threshold works — at any resolution. Setting it loose enough
          to catch real fraud would flag every honest customer.
          

          
          Design response: anchor detection on data that survives compression —
          the UTR reference number (rule R1) and the exact file bytes (rule R2).
          This is the single most important architectural decision in the project.
